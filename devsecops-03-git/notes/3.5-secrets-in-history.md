## Why a committed secret won't die
- Deleting a secret in a later commit does **not** remove it — it's in every past commit (the Merkle chain from 3.1). Anyone with the repo can check out the old commit and read it.

## Detecting secrets — Gitleaks
- Run locally against the repo / working tree.
- Install as a **pre-commit hook** so secrets are caught *before* they're committed.
- Integrate into **CI** so the PR fails if a secret is present (shift-left, ties to 3.2 required status checks).
- _Add the exact commands you used._

## The only real fix: rotate
- Treat a leaked credential as **compromised** → invalidate the old one, issue a new one.
- Scrubbing history (`git filter-repo` / BFG + force-push + everyone re-clones) is *extra* — and you **still** rotate, because you must assume it leaked.

## 🔐 Cloud mapping
- Rotate leaked secret → **IAM access-key rotation** / short-lived **STS** credentials.
- Prevention → secrets manager (Vault / AWS Secrets Manager), `.gitignore`, pre-commit + CI scanning.
