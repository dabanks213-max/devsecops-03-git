# 3.3 — Remotes

Your local `.git` holds everything — but it **dies with the laptop** and nobody else can reach it. A **remote** (GitHub) is the shared source of truth + backup. `origin` is just a nickname for the remote URL.

## The four commands, two directions
| Command | Direction | What it does |
|---|---|---|
| `git clone <url>` | down (once) | Download the repo + full history (own clean dir) |
| `git push` | up | Send your new commits to the remote |
| `git pull` | down | Fetch **and merge** the remote's new commits |
| `git fetch` | down | Download **without** merging |

Other useful ones:
- `git remote -v` — which URLs `origin` points at
- `git remote add origin <url>` — connect a local repo to a remote
- `git push -u origin <branch>` — push **and link** (track) the branch, first time
- `git pull --rebase` — bring changes down without a merge commit

## 🔐 Security
- **Push auth** (SSH key or token/credential manager) is a **separate gate** from branch protection. Being authenticated gets you through the door; it does **not** grant permission to push to a protected branch.
- Cloning a **public** repo needs no auth; auth kicks in on the first **push**.

## Mental note
Your local view of a branch **lags the remote** until you `pull`. After a teammate (or a merged PR) updates `origin/main`, your local `main` still shows the old commit until you `git switch main && git pull`.

## Cloud mapping
Git-as-a-service with access control = **AWS CodeCommit** (IAM-controlled). A push is the **entry point to CI/CD**, so repo security = pipeline security.
