# 3.4 — Undoing Mistakes

**There is no single "undo." There are three, and one question picks the right one: *have you already pushed it?***

```
  Not committed yet   →  git restore   (throw away edits)
  Committed, not pushed →  git reset    (rewrite local history)
  Already pushed      →  git revert    (undo forward — add a new commit)
```

## `git restore` — discard *uncommitted* work
- `git restore <file>` / `git restore .` — discard edits (⚠️ no safety net — never committed, can't recover)
- `git restore --staged <file>` — just un-stage, keep the edit
- Look before you undo: `git status`, `git diff`.

## `git reset` — undo a *local, unpushed* commit
Slides the branch pointer back; commits after it drop off. Three strengths:
| | History | Staging | Files |
|---|---|---|---|
| `--soft` | rolled back | kept, staged | untouched |
| `--mixed` (default) | rolled back | unstaged | untouched |
| `--hard` | rolled back | **wiped** | **wiped** ⚠️ |

**Rewrites history** → safe locally, dangerous once shared (same as the rebase rule).

## `git revert` — undo something *already pushed*
Creates a **new commit that is the inverse** of the bad one. The bad commit stays in history; its effects are undone. Nothing rewritten → **safe to push**.
- Conflict during a revert? Hand-edit to the correct end state → `git add` → `git revert --continue`.

## 🔐 Security
- A **pushed secret** is *not* fixed by `revert` or deleting it later — it's still in every past commit (the Merkle chain). The only real fix is to **rotate the credential**. (→ 3.5)
- On a **protected branch**, even a `revert` goes through a PR.
- Before anything risky: `git branch backup-before-reset` — a branch is free insurance.

## Cloud mapping
`revert`-not-`reset` on shared branches = **immutable audit log** (CloudTrail) · GitOps rollback = `git revert` the infra commit · rotate creds = IAM key rotation / STS.

## Did it live
Reverted a pushed bad change, hit a **real merge conflict**, and resolved it by hand to the correct end state — audit trail preserved (both the mistake and its fix visible in `git log`).
